# B2B Platform — Slice 5: CRM SKUs, subscriptions and entitlements — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The CRM becomes paid SKUs on a subscription billed outside the wallet: every agency has a plan (Starter free / custom SKUs / Suite) with seats, a trial and READ_ONLY on expiry; every controller is classified to a SKU (or never gated) and enforced with 402 `SKU_REQUIRED`; the frontend hides locked nav and shows a LockedFeature card; platform admins set plans, seats, waivers and mark invoices paid; a monthly job raises subscription invoices with a Razorpay payment link (stub until keys).

**Architecture:** Public tables `subscription` and `subscription_invoice` (+ `gateway_order` purpose SUBSCRIPTION from slice 2). `Entitlements` (skus, seats, status) resolved from `subscription` + `tenant.status` and cached next to status in `TenantCache`, updated in the same method as every change. One `EntitlementInterceptor` (runs after `TenantStatusInterceptor`) looks up an **explicit table** `controller class → Sku | NEVER_GATED`; a contract test walks `RequestMappingHandlerMapping` and fails on any unclassified controller (also wired into `blueprint-audit.sh`). READ_ONLY = GET + the existing read-style POST allow-list. The slice 2 gateway webhook routes SUBSCRIPTION orders to `SubscriptionBillingService.markPaid`.

**Tech Stack:** as slices 2–4; invoice PDF via the existing OpenPDF utilities used for client invoices.

**Spec:** `/Users/shivanshsrivastava/Projects/Voyra global/B2B_PLATFORM_DESIGN.md` §5.2 (SKUs, prices, rules), §6 (subscription, subscription_invoice), §7.6, §8 (entitlements — follow exactly), §9 (Subscription screens).

**Deviations (rulings):**
- **Prices** are platform settings (`sku_prices` JSON, defaults from spec §5.2: CRM Core 2499, Seats 399/seat, Accounts & GST 1999, Reports 699, Visa 499, Suite 4999 incl. 5 seats; annual = 10 months) so the owner can change them without a release; GST 18 % on subscription invoices (Voyra's own service).
- **Existing agencies** migrate to Suite: house tenant and the tenants named in platform setting `founding_agencies` (default: the tenant named "Voyra Global" if present — matched by name, never modified otherwise) get `waived_reason = FOUNDING_AGENCY`; every other existing agency gets a 90-day complimentary Suite (`waived_reason = COMPLIMENTARY`, `period_end = now + 90 d`). New agencies approved from now get a 14-day Suite TRIAL.
- **Emails** (14/7/1-day expiry) go through `NotificationService` (logging) like slice 2; SMTP is slice 6.
- **Voyra's invoice series** for subscriptions: `VOY-SUB-<yyyy>-<seq>` in a public sequence table.

## Global Constraints

- All earlier slices' Global Constraints hold. Next free public migration after slice 4's.
- **Never gated** (spec §8): `/api/auth/**`, `/api/public/**`, `/api/reference/**`, `/api/platform-bookings/**`, `/api/wallet/**`, `/api/flights/**`, `/api/hotels/**`, `/api/agency/profile`, `/api/platform/**` — classify those controllers NEVER_GATED; everything else gets exactly one SKU per spec §5.2's "Unlocks" column. `SUPER_ADMIN` bypasses and is audit-logged when it acts with `X-Tenant-Id`.
- Refusal: HTTP 402 `{code: "SKU_REQUIRED", sku: "<SKU>"}`; READ_ONLY write: 402 `{code: "READ_ONLY"}` (suspended agencies keep their 423 from slice 1).
- **READ_ONLY never locks anyone out and deletes nothing.**
- Seats = `COUNT(agent WHERE deleted_at IS NULL AND is_active)`; checked on agent/accountant create **and reactivate**; existing logins never cut off.
- Public proposal / feedback links of an agency without CRM Core (or READ_ONLY) render "This link is no longer available".

## Review Focus

1. A controller added later without a classification — the contract test fails the build. Task 2.
2. Trial ends while an agent is mid-edit — next write gets READ_ONLY 402, reads keep working, nobody is logged out. Task 2 + Task 5.
3. Owner deactivates then reactivates an agent at the seat limit — reactivate refused with a seat message. Task 3.
4. The same Razorpay payment webhook for a subscription invoice delivered twice — invoice paid once; never touches a wallet. Task 4.
5. Founding-agency waiver: no expiry, no invoice, never READ_ONLY. Task 1 + Task 4.

- Public migration: `subscription(tenant_id UNIQUE, plan STARTER|CUSTOM|SUITE, skus TEXT[], seats INT, status TRIAL|ACTIVE|PAST_DUE|READ_ONLY|CANCELLED, period_start, period_end, trial_ends_at, waived_reason NULL|FOUNDING_AGENCY|COMPLIMENTARY|GMV_THRESHOLD, billing_cycle MONTHLY|ANNUAL, updated_at)`, `subscription_invoice(id, tenant_id, number UNIQUE, period_start, period_end, lines JSONB, amount, gst, total, status DRAFT|ISSUED|PAID|VOID, due_at, gateway_order_id, paid_at, paid_via, pdf_key, created_at)`, `voyra_invoice_sequence`; backfill per the ruling; settings `sku_prices`, `founding_agencies`.
- `Sku` enum (CRM_CORE, STAFF_SEATS, ACCOUNTS_GST, REPORTS, VISA); `Entitlements` record; `EntitlementService.resolve(tenantId)` (SUITE = all SKUs + 5 seats included; waived/trial/active → full access to its SKUs; READ_ONLY flag) cached in `TenantCache` (put/evict in the same method as every subscription change); provisioning creates the 14-day TRIAL; `LoginResponse.entitlements`.

### Task 4: Billing — invoices, payment link, webhook, lifecycle job
- `SubscriptionBillingService`: monthly/annual invoice (lines per SKU/seat from `sku_prices`, GST 18 %, number from the sequence, PDF), `gateway_order(purpose SUBSCRIPTION, ref_id = invoiceId)` + payment link via `PaymentGateway` (stub until keys); webhook `SUBSCRIPTION` purpose → `markPaid` (idempotent by payment id; never a wallet call); admin mark-paid (bank) and void.
- `SubscriptionLifecycleJob` (daily): raise invoices at period end (not for waived/trial); ISSUED past due → PAST_DUE; PAST_DUE + 7 days → READ_ONLY; TRIAL/COMPLIMENTARY end → READ_ONLY directly; paid → ACTIVE with next period; 14/7/1-day expiry notifications.
- Tests: Review Focus 4 and 5; each lifecycle transition; GST/lines arithmetic; duplicate webhook.
