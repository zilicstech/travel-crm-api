# Bookings Module Rework, Flight Dates, Lead Default Members

**Goal:** A clean, searchable bookings list with a real per-agency booking number, one "Manage booking" page that holds every booking action, cancellation moved off the lead, dates on flight search results, and new leads starting with 1 traveller.

**Branch:** `feat/bookings-and-refunds` in both repos (one branch and one PR per repo, not merged yet).

## Decisions

- **Booking number:** a per-tenant Postgres sequence. Each tenant has its own schema, so `booking_number_seq` in the tenant schema is naturally per agency, gap-tolerant and race-free. Shown as `BK-00042`: zero-padded to 5 digits, and longer once past 99,999. Existing bookings are numbered in the order they were created.
- **List page:** server-side search, sort and paging, so it stays fast at thousands of bookings. Search matches the booking number (`42`, `BK-42`, `BK-00042`), client name, destination and PNR or reference. Sortable columns are booking no., client, price, booking date and travel date.
- **List columns:** Booking no. · Client · Service (type icon and destination) · Travel date · Booked on · Price · Status (booking and payment) · Manage. Profit and margin move to the Manage page. The metric cards are removed; the dashboard already shows those totals.
- **Manage booking page:** `/agency/bookings/[id]` and `/agents/bookings/[id]` share one component. It has a header (number, status, client, lead link), money (price, cost, profit for the owner, invoiced, received), details (reference, supplier, dates, travellers), documents inline, and a labelled Actions panel:
  - Confirm, or Mark completed;
  - Edit pricing (owner);
  - Deadlines;
  - Supplier costs;
  - History (owner);
  - Request feedback (completed bookings);
  - Delete (when there are no accounting records);
  - Cancel booking, in a separate danger area.

  Cancelled bookings show a Cancellation panel: type, reason, charges, the refund to the customer, the refund from the supplier, and the cross-check.
- **Lead booking card:** the Cancel booking button is removed. A "Manage" link opens the Manage page. Delete stays on the card.
- **Flight dates:** results carry `departDate` and `arriveDate`. Tripjack takes them from the segment datetimes. Mock uses the search date, plus a day when the arrival crosses midnight. Each card shows "Fri, 20 Nov" under each time, and the arrival is marked "+1" when it lands on a later day.
- **New lead:** Adults starts at 1, not 2.

## Tasks

### Backend
1. **Migration and model.**
   - V52 adds the tenant sequence and a `booking_number BIGINT NOT NULL UNIQUE DEFAULT nextval(...)` column, backfilled by created date.
   - `Booking.bookingNumber` is generated by the database on insert.
   - `BookingResponse` gets `bookingNumber` and `bookingRef`.
2. **List search and sort.**
   - The list takes `q` and `sort` (`bookingNumber|clientName|sellingPrice|bookingDate|journeyDate`, `,asc|desc`). The default sort is newest booking number first.
   - Add a spec for `searchMatches(q)`.
   - Agent scoping is unchanged.
3. **Flight dates.**
   - Add `departDate` and `arriveDate` to the offer and group DTOs, and carry them through grouping and paging.
   - Tripjack parses the date from `dt`/`at`; mock derives it.
4. **Tests.**
   - Search spec on number, client and PNR.
   - Sort whitelist, so an unknown key gets 400.
   - Mock arrive date across midnight.
   - Tripjack date parsing.
   - `mvn verify` passes.

### Frontend
5. **New lead:** Adults starts at 1.
6. **Flight cards:** show the date under each time, and "+1" when arrival is on a later day.
7. **Shared list:** one `BookingsList` component used by both bookings pages, with search, filters (status, type, and agent for the owner), sortable headers, paging and a Manage button per row.
8. **Manage page:** one `BookingManage` component for the two `[id]` routes, reusing the existing modals (pricing, deadlines, cost components, documents, history, cancel).
9. **Lead card:** remove Cancel booking and add a Manage link. Show `BK-` numbers on the lead card and the Refunds page.
10. **Checks:** `tsc` and lint on the touched files, the build, and a Chrome check.
11. **Regression:** run the `regression-tester` agent in pre-merge mode, fix what it finds, and update the PR descriptions.

## Not in scope

- Editing booking details beyond pricing. There is no edit form today, and the existing `PUT` stays API-only.
- Accountant access to the Manage page. Accountants work from Accounts.
- Bulk actions and export.
